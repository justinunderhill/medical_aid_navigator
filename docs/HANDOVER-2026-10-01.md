## Subsequent request: automatic PWA update detection

The user requested refresh support when changes are pushed. Added a deployment
version shared by Next's build ID, browser bundle, `/api/version`, and `/sw.js`.
The service worker is now generated at the same URL on every deployment and
waits for explicit acceptance. The user sees **Refresh now** or **Later**, with
a warning that refresh clears chats, selected PDFs and unfinished checks.

Checks run every five minutes while visible, on focus/visibility return and on
reconnection. Offline/invalid checks do not prompt or discard the session.
**Later** defers the banner for fifteen minutes. Worker activation in another
tab does not automatically reload this tab. Version checks work even if service
workers are unsupported. Old cache cleanup only removes this app's caches.

The 83-test suite covers update detection, no forced first-install refresh,
offline checks, multi-tab activation, opt-in activation, single reload, cleanup,
and service-worker cache isolation. The release smoke script now verifies that
the uncached version endpoint and worker script contain the same version.
Local runtime checks also confirmed the build ID, compiled browser version,
version endpoint and worker cache name match. npm's prebuild hook writes one
ignored `.app-build-version` UUID for all build workers and later server restarts.
Existing open sessions predating this feature need one refresh to receive it.

## Subsequent request: mobile MAN chat

The user reported that MAN did not look like a chat, the response ellipsis was
static, and the screen did not fit their Oppo A78 5G. MAN now uses distinct
message bubbles, shows the sent question immediately, and displays three
staggered animated typing dots with a readable status and reduced-motion support.
Failed requests restore the message for retry; clearing chat still aborts work.

The dedicated `/man` and `/cover` routes use a viewport-sized flex shell with
an independently scrolling conversation and pinned composer. Android keyboard
resizing uses both interactive-widget metadata and visualViewport resize/scroll
events. Compact available heights hide surrounding chrome; safe-area spacing
and navigation are included in the layout. Privacy details remain accessible
inside the conversation. Home also uses the new chat presentation.

Chrome responsive checks covered 360px width and a 320 x 360 reduced-height
viewport, immediate message display, the typing animation, and a real AI reply.
Physical Oppo keyboard/PWA behaviour still needs a check on the user's device.
